# 麦麦电话闹钟（local.wake-call）v1.0.0

到点给手机打一通真的电话：MaiBot 用模型生成一句话，做语音合成，经 SIP 拨到你手机上，
手机出现原生来电界面，接起来就是那句话。不依赖 QQ，也不需要 root 或安卓系统权限。

> **单向播放，不能对话。** 接通后只有手机那头能听到 MaiBot 说话，你对着手机说什么它都听不见；
> 台词播完就自动挂断。这是设计如此，不是线路坏了——原因见下面「它是单向的」一节。

## 五分钟上手（最短可行路线）

下面的文档加起来几千字，但**真正必须做的只有四步**。先跑通，再回头补细节。

前提：插件已经放进 `bots/<bot_id>/plugins/` 并重启过，侧边栏能看到「麦麦电话闹钟」。
还没装的话看下面的「安装」一节，两分钟的事。

| # | 做什么 | 耗时 |
|---|---|---|
| 1 | 手机装 **Linphone**，首次启动选「第三方 SIP 账号」，**别选**「创建 Linphone 账号」 | 3 分钟 |
| 2 | 去 <https://sip2sip.info> 注册**两个**免费账号（一个给 MaiBot 拨，一个给手机接） | 3 分钟 |
| 3 | 侧边栏「SIP 账号」卡片：主叫填第一个号 + 密码，被叫填第二个号，**SIP 服务器填 `proxy.sipthor.net`** | 1 分钟 |
| 4 | 点「试拨」。手机响了、接起来听到一句话 → 配好了 | 1 分钟 |

四步走完，再去设时间、写提示词，剩下的章节全是排错和进阶，现在不用看。

**只有三个地方会让人卡住**，提前说清楚：

1. **别用 Linphone 官方号**（`@sip.linphone.org`）。它能振铃、能接通，但整通经常没声音——
   那个号的定位是 Linphone 客户端之间互拨，对第三方程序（插件用的 baresip）不友好。
   用 sip2sip 这类服务。
2. **Linphone 里把 PCMA 关掉**（设置 → 音频 → 编解码器，只留 PCMU）。不关的典型症状是
   「接通了，但一句都听不到」。
3. **ffmpeg、baresip 和 edge-tts 要单独装**。Debian / Ubuntu / proot 两行命令：
   `apt install -y baresip baresip-modules ffmpeg`，再用 MaiBot 那个 Python 补一个包
   `/opt/MaiBot/.venv/bin/pip install edge-tts`。
   缺 ffmpeg 是「接通但没声音」，缺 edge-tts 是根本合不出语音。
   macOS / Windows 的装法见「运行前置」一节。

## 它是单向的：只能听，不能对话

接通之后发生的事只有一件：插件把一句话播给你听，播完主动挂断（发正常 BYE，不是超时断线）。

整条链路上**没有麦克风采集**。baresip 只加载 `stdio / aufile / g711 / account / menu` 五个模块，
配置里写死 `audio_player aufile,/dev/null` —— 从手机收到的音频直接丢给 `/dev/null`，不落盘、不解析。
发送方向默认是一个静音 WAV，接通后才用 `/ausrc` 换成合成好的台词。

| 你期待的 | 实际 |
|---|---|
| 像打电话一样跟麦麦聊两句 | 不行。你说的话不会被识别、不会进模型、不会有回复 |
| 对着手机喊「我起来了」，让它回一句 | 不行。它不知道你有没有起来 |
| 当语音助手 / 对讲机 / 远程哄睡 | 都不适用，换别的方案 |
| 闹钟响了，听到她叫你 | 可以。这就是它唯一的目标 |

为什么不做双向：

1. **没有采集通路。** 跑 MaiBot 的环境（proot、Docker、云服务器）普遍没有声卡，
   要接麦克风得额外配 ALSA / PulseAudio，多数用户根本起不来。
2. **实时对话不是这个插件的目标。** 真要做语音通话，需要全程推流 + VAD + 流式 TTS，
   延迟、打断、回声消除每一项都是独立工程，跟「到点响一声」不是一个量级。
3. **单向反而可靠。** 链路只有「合成 → 编码 → 播放」一条直线，没有上行协商，
   也就不存在「双方编码不一致导致单向静音」这类问题。

> 怎么确认单向是正常的：接起来听到完整一句话 → 你说话那头毫无反应 → 然后自动挂断。
> 三条都对，说明链路是通的。

## 为什么不用 QQ 发语音

最省事的做法本该是让麦麦在 QQ 上发一条语音消息。没这么做，有三个具体原因。

**一、闹钟要的是「吵醒」，不是「收到一条」。**

QQ 语音本质是消息：手机亮一下、响一声提示音，然后安静。静音、免打扰、锁屏折叠、
消息被折叠进「不重要通知」——任何一种都能把它吃掉，而你根本不会知道它来过。
SIP 来电走的是系统通话通道：全屏亮起、持续振铃、可以设成穿透免打扰，
接起来就是人声。这个差别在早上六点半是决定性的。

**二、账号风险，而且不值得赌。**

QQ 有官方的机器人开放平台，但要开发者资质审核、能力按模板给，普通个人号很难直接跑起来；
社区里的方案（NapCat、Lagrange 这类协议端）走的是另一条路——模拟官方客户端登录。
这条路不属于腾讯开放的能力，因此账号被风控处理是有先例的。平时聊天掉线顶多重连一次，
但这个插件是**每天固定时间**主动私聊、定时推语音，规律性行为恰恰是风控最容易识别的特征。
真被限制或封号，搭进去的是一个常用账号，闹钟也跟着一起哑。
SIP 完全不碰这条线：它不经过任何社交平台，最坏情况只是换个服务商，不牵连账号。

**三、链路越短，到点越响。**

QQ 方案的链路是：QQ 服务器 → 协议端（要扫码登录、token 会过期、版本更新可能不兼容）→ MaiBot → 手机。
四环里任何一环断掉，到点就是没声音，而且往往断在你最需要它响的那天早上。
SIP 方案只有三环，中间那台服务器还可以换成自己搭的。

**代价。** 要多注册两个 SIP 账号、手机多装一个 Linphone——就是上面那四步。
一次性配完，之后每天只剩「等电话响」这一件事。

## 安装

**拿到代码**，两种都行：

- **下载发布包（推荐）**：[最新 Release](https://github.com/mamaipiye/maibot-wake-call/releases/latest)
  里的 `maibot-wake-call-v1.0.0.zip`，解压后就是一个现成的插件目录。
- **克隆仓库**：`git clone https://github.com/mamaipiye/maibot-wake-call.git`

然后：

1. 在 `MaiBot/bots/<bot_id>/plugins/` 下建一个目录（例如 `local_wake_call`），
   把本仓库的文件平铺进去——`_manifest.json` 必须直接在 `local_wake_call/` 里，
   不要再多套一层。
2. 重启 MaiBot，侧边栏出现「麦麦电话闹钟」。
3. `config.toml` 由插件首次加载时自动生成，不用手写；要改字段就照 `config.example.toml` 抄。
4. 保持 `[plugin].config_version` 不动，升级时插件靠它补新字段。

## 第一步：注册 SIP 账号（用 sip2sip，别用 Linphone 官方号）

插件只负责「拨」，接电话的是手机上的 SIP 客户端。两者之间要经过一台 SIP 服务器，
所以要**两个账号**：一个给 MaiBot 当主叫，一个给手机当被叫。同一个号会自己拨自己。

**先别用 Linphone 官方账号（`@sip.linphone.org`）。** 它的定位是「Linphone 客户端之间互拨」，
第三方 UA（插件用的 baresip 就是）接上去常见的情况是：能注册、能振铃、能接通，**但整通没有声音**。
用它排错会把一个账号问题误判成插件问题，白花几小时。

推荐 <https://sip2sip.info>（AG Projects 提供的免费公共服务，对标准 SIP UA 友好，自带 NAT 穿透中继）：

1. 打开 <https://sip2sip.info>，填名字、想要的账号名、密码、邮箱。
2. 收邮件点验证链接。账号地址就是 `你的账号名@sip2sip.info`。
3. **服务器地址记成 `proxy.sipthor.net`** —— sip2sip 的账号域名解析不出来，必须单独填这一项。
4. 注册两个，比如 `bot` 和 `me`。

> sip2sip 是免费服务，按公平使用策略运行（超出平均用量 10 倍会被停），且不提供任何保证。
> 一天一两通闹钟完全在正常范围内。介意的话就自建 SIP，见后面「云服务器 + 自建私有 SIP」。

## 第二步：手机装 Linphone

推荐 **Linphone**（开源、免费、三端都有）：

| 平台 | 下载 |
|---|---|
| Android | [Google Play](https://play.google.com/store/apps/details?id=org.linphone) ／ [F-Droid](https://f-droid.org/en/packages/org.linphone/) ／ [官网 APK](https://download.linphone.org/releases/android/) |
| iOS | [App Store](https://apps.apple.com/app/id360065638) |
| 桌面（可选） | <https://linphone.org/en/download> |

首次启动选 **「第三方 SIP 账号」**（不要选「创建 Linphone 账号」），按下面填：

| 字段 | 填什么 |
|---|---|
| 用户名 / Username | `me`（sip2sip 的账号名，不要带 `@` 后面的部分） |
| 密码 | sip2sip 的后台密码 |
| 域名 / Domain | `sip2sip.info` |
| 代理 / Proxy | `proxy.sipthor.net` |
| 传输 | UDP（同一 WiFi 或家里网络）；网络挑剔时改 TLS |

### 必须关掉 PCMA（G.711 A-law）

这一步最容易漏，漏了就是「接通了但没声音」，而且日志里一个字都不会报错。

插件侧只发 **PCMU（G.711 μ-law）**——baresip 只加载 `g711.so`，账号行固定写死
`audio_codecs=pcmu/8000/1`。但 Linphone 默认同时启用 PCMU 和 PCMA，部分机型/版本会优先挑 PCMA，
而 PCMA 在这条链路上是零字节：来电照响、接通照成功、对方什么都听不到。

操作：Linphone → **设置 → 音频 → 编解码器**（不同版本叫「音频编解码器」/ Audio codecs），
把 **PCMA / G.711 A-law 取消勾选**，只留 **PCMU / G.711 μ-law**。

顺手把 Opus、G.722、Speex 之类的宽频编码也关掉：8k 窄带链路上它们不会更好听，
只是多一个协商出意外的机会。

### 装完必须做的权限设置

否则锁屏后不会响：

1. **允许通知**，并把 Linphone 的通知设为「优先 / 允许打扰」。
2. **允许后台活动**，在系统设置里把 Linphone 的电池优化设为「不限制 / 无限制」。
3. 国产 ROM 还要额外开**自启动**和**后台弹出界面**权限（小米、华为、OPPO、vivo 都有各自入口）。
4. 打开 App 确认账号状态是「已连接」。

### 先自测一次，再动插件

在 Linphone 里拨 **`sip:4444@sip2sip.info`**（sip2sip 提供的回声测试号），
能听到自己说话就说明账号、注册、媒体三条线都是通的。这一步通过之后再配插件——
出问题时你就能确定「不是账号的问题」。

> 公网 SIP 的来电靠推送唤醒 App，锁屏久了可能有几秒延迟。
> 走 sip2sip 这类海外服务器时，接通后前几秒还可能整段静音（媒体被境外中继收敛），
> 闹钟场景正好丢掉开头那句——这就是本插件把「内网直呼」做成默认开启的原因。
> 手机和 MaiBot 在同一张 WiFi 上时它会自动绕开服务器，见下节。

## 运行前置（两个外部程序 + 一个 Python 包）

插件本身是单文件 Python，但有两件事 Python 做不到，必须调用系统里的独立程序；
另外默认的语音后端要额外装一个包。

| 依赖 | 干什么 | 缺了会怎样 |
|---|---|---|
| `baresip` + `stdio / aufile / g711 / account / menu` 模块 | 真正发起 SIP 呼叫、播放音频 | 拨不出去，日志报「找不到 baresip」 |
| `ffmpeg` | 把 TTS 音频转成电话能播的 8k 单声道 WAV | **电话能接通，但一句都听不到** |
| `edge-tts`（Python 包） | 默认的后端，把台词合成 mp3 | 试拨和正式拨号都失败，日志报 `edge-tts 失败`；换 OpenAI / MiniMax / 豆包后端可绕开 |

**它们不会跟插件一起下载。** 插件的 zip 只有几百 KB，而 ffmpeg 单独就有几十 MB；
更重要的是各平台的二进制互不通用，打包进来反而会在别的系统上跑不起来。所以走系统包管理器装。

### edge-tts 要装进 MaiBot 那个 Python

插件调用的是 `sys.executable -m edge_tts`——也就是**跑着 MaiBot 的那个解释器**，不是系统 `python`。
所以要用 MaiBot 虚拟环境里的 pip：

```bash
# 按你实际的安装路径改；下面是常见位置
/opt/MaiBot/.venv/bin/pip install edge-tts
# 或：cd /opt/MaiBot && .venv/bin/pip install edge-tts
```

装完可以验一下，能打出帮助信息就算成了：

```bash
/opt/MaiBot/.venv/bin/python -m edge_tts --help
```

不想动 venv 也可以：在插件目录下建一个 `vendor/`，把 `edge_tts` 包的内容放进去，
插件启动合成时会自动把 `vendor/` 加进 `PYTHONPATH`。

> 用的是微软公开的朗读接口，不需要 API key，也不需要梯子。
> 如果环境完全连不上外网，就把 TTS 后端换成 OpenAI 兼容 / MiniMax / 豆包。

### ffmpeg 是干什么的（为什么绕不过去）

语音合成的结果（edge-tts、豆包）都是 mp3 这类压缩音频。但 SIP 电话用的是 G.711 窄带编码，
baresip 的播放模块只吃**未压缩的 WAV**，而且必须是 **8000 Hz、单声道**。
中间这层「解码 → 重采样 → 混单声道」只能靠 ffmpeg。

所以缺 ffmpeg 的表现很具迷惑性：**手机照常响、接通照常成功、但全程没有声音**，
既不是账号问题也不是编解码协商问题。

### 怎么装

| 系统 | 命令 |
|---|---|
| Debian / Ubuntu / proot | `apt install -y ffmpeg` |
| 一次性装全（含 baresip） | `apt install -y baresip baresip-modules ffmpeg` |
| macOS | `brew install ffmpeg` |
| Windows | `winget install Gyan.FFmpeg`，或去 <https://www.gyan.dev/ffmpeg/builds/> 下 essentials 版 |

Windows 手动装 zip 的要注意：解压后把里面的 `bin` 目录加进系统 PATH，**加完要重开终端**，
然后在终端里跑 `ffmpeg -version`，有版本号输出才算成功。只在文件管理器里双击测试不算，
因为插件调用的就是你终端里那个 `ffmpeg`。

### 装完怎么确认

插件启动时会自检 `baresip` 和 `ffmpeg`，缺哪个就在侧栏「环境自检」直接显示
**「baresip 缺失」** 或 **「ffmpeg 缺失」**，日志里也会打一条带安装命令的 warning。
不用等到闹钟响才发现。

`edge-tts` 是 Python 包，不在这个自检范围内——缺了要到第一次合成才暴露，日志里是
`edge-tts 失败: No module named edge_tts`。用上面那条 `--help` 命令提前验一下最省事。

## 账号准备（插件侧）

1. 主叫（拨号端，跑 MaiBot 的那台）：填完整 SIP 地址 + 密码，例如 `sip:bot@sip2sip.info`。
   - sip2sip：「SIP 服务器」**必须**填 `proxy.sipthor.net`——它的账号域名解析不出来。
   - 自建 Asterisk / 公司 PBX：服务器填 PBX 地址，可带端口（`1.2.3.4:5080`）。
2. 被叫（接听端，手机）：填手机 Linphone 上登录的那个号，例如 `sip:me@sip2sip.info`。
3. 先在侧边栏点「试拨」，确认手机能响、接起来能听到声音，再设时间。

> 试拨固定用 edge 朗读，不会动你配置里的正式音色——打完不用改回去。
> 试拨会先走内网直呼（同一 WiFi 时），找不到才走 sip2sip。两条路都验过，闹钟才靠得住。

## 最小可用配置

```toml
[sip]
caller_aor = "sip:你的主叫@sip2sip.info"
caller_pass = "主叫密码"
server = "proxy.sipthor.net"     # sip2sip 必填；自建 PBX 填 PBX 地址
callee_aor = "sip:你的被叫@sip2sip.info"

[tts]
backend = "edge"                 # 免费、免密钥；前提是装过 edge-tts 包（见「运行前置」）
```

其余项保持默认即可。想换音色 / 换后端、改台词人设、改台词守门，都在侧边栏里点。

## 内网直呼（可选，但强烈建议）

同一 WiFi 下把 INVITE 直接发给手机的局域网地址，语音不出局域网，延迟低、不依赖公网服务器。

- **家里 / 宿舍（同一 AP）**：什么都不用填。插件会自己扫本网段找到手机。
- **校园网 / 公司网（跨 /24）**：第一次在「内网直呼目标」里填手机的局域网 IP，
  端口留空（插件自己扫）。之后手机换了 IP，插件会拿记住的端口扫一遍网段把它找回来。

找不到对端时，输入框下面会直接写出原因：是「已经扫过本机 /20 和记住过的网段但没人应答」，
还是「距上次扫描不到 60 秒，这次没重扫」。两种情况的处理办法不同，所以分开说。
扫了确实没有，就在框里手填一次对方 IP——这段地址会被记住，下次优先扫。

相关开关（侧边栏「SIP 账号」卡片内）：

| 项 | 默认 | 说明 |
|---|---|---|
| 同一局域网时走内网直呼 | 开 | 找不到对端就自动走公网，不会打不通 |
| 端口失效时自动扫描找回 | 开 | Linphone 端口每次启动都变，这一步负责自愈 |
| 对方换了 IP 也自动找回 | 开 | 拿记住的端口扫本机网段，校园网换 /24 也不用重填 |
| 找回范围 | /20 | `/24` 更收敛；`/20` 适合按大网段分池的校园网 |
| 内网没接通就回退公网 | 开 | 建议保持开启 |

## 云服务器 + 自建私有 SIP（跳过海外服务器）

上面两节都假设「拨号机和手机在同一张局域网」。如果你把 MaiBot 部署在带**公网固定 IP** 的云服务器上，
内网直呼就没有意义了——这时推荐自建一个轻量 SIP 服务，彻底避开 sip2sip 这类海外服务器的
「接通后前 6 秒静音」（媒体被塞进境外 MediaProxy 收敛导致，闹钟场景直接不可用）。

最小拓扑：

1. 云服务器上跑一个轻量 SIP 服务（Asterisk / Kamailio 最小配置即可），开两个分机：
   `1001` 给 MaiBot、`1002` 给手机 Linphone。编码只留 `ulaw/pcmu`——PCMA 在这条链路上是零字节。
2. 安全组放行 `5060/udp+tcp`，外加一小段 RTP 端口（如 `10000-10100/udp`）。
3. 手机 Linphone 登录 `1002@云服务器公网IP`，传输建议选 **TCP**：
   运营商对 UDP 映射的回收比 TCP 激进得多，而闹钟每天只响一两次，连接必须撑得住整夜。
4. 插件配置（`config.toml` 的 `[sip]` 段）：

```toml
lan_call_enabled = false        # 部署在云端就关掉这一项
server = "127.0.0.1"            # 同机部署填本机；改过端口就写 127.0.0.1:5080
transport = "tcp"               # 留空 = UDP
caller_aor = "sip:1001@127.0.0.1"
caller_pass = "分机 1001 的密码"
callee_aor = "sip:1002@127.0.0.1"
```

几个细节：

- `server` 可以带端口（`1.2.3.4:5080`），也可以写 `[IPv6]:port`；不写端口按 5060。
- `transport` 只影响公网拨号。填 `tcp` 时 baresip 的 accounts 行会带 `;transport=tcp`；
  留空或填别的值一律按 UDP。内网直呼永远走 UDP，不受它影响。
- `module_path` 默认 `/usr/lib/baresip/modules`。Ubuntu 实际在
  `/usr/lib/x86_64-linux-gnu/baresip/modules`、源码编译在 `/usr/local/lib/baresip/modules`，
  插件在默认路径不存在时会按常见路径自动兜底，并在日志里写明换成了哪个。

## 台词守门

模型或中转站返回「限流 / 额度不足 / 我无法协助」这类文本时，这些字会被念出来，而且按字数计费。
守门在送进语音合成前做两道闸：

1. **词表闸**：命中内置禁用词 → 判废，改说本地备用台词（十句，随机且不重复上一句）。
2. **字数闸**：无论什么情况都截到设定上限内。

词表、字数上限、备用台词都可以在侧边栏改，也可以整体关闭。

## 常见问题

**能对话吗？我说话它听得见吗？**
不能，这是单向的。链路只往下行走：生成台词 → 合成 → 经 SIP 播到你手机 → 挂断。
没有麦克风采集模块，手机端的声音不会被接收，也不会进模型。
详见上面「它是单向的」一节。

**手机不响**
按顺序查：日志里「走内网」还是「走公网」→ 主叫是否注册成功（日志里找 `200 Ok` 或 `401`）
→ 手机 Linphone 是否显示「已连接」→ 先用手机拨 `4444@sip2sip.info` 验证账号通不通
→ 通知权限与电池优化是否放开（见「第二步」）。

**响铃、接通了，但整通没声音**
两个原因，按顺序查：

1. **ffmpeg 没装**：侧栏「环境自检」显示「ffmpeg 缺失」就是它。没有 ffmpeg 就没有可播的 WAV，
   baresip 拿到的是空文件——电话照通，声音为零。
2. **PCMA 没关**：插件只发 PCMU，手机如果留着 PCMA 并被优先选中，同样是接通成功 + 零字节。
   去 Linphone 设置里把 PCMA / G.711 A-law 取消勾选，只留 PCMU。

**只有一方听得见**
先分清是哪一头听不见，这两种情况性质完全不同：

- **手机那头听不见（你接起来是哑的）** —— 这才是故障。多半是编码协商两侧不一致：
  两侧都只留 PCMU，别混着用「一侧 PCMU + 一侧 PCMA」；自建 SIP 还要检查分机配置里 `ulaw` 是否排第一位。
  也可能是 ffmpeg 缺失或 PCMA 没关，见上一条。
- **你这头听不见手机说话** —— 不是故障，是设计如此。本插件不上行采集，你说话它听不见，
  详见「它是单向的」。

**锁屏久了收不到，解锁就弹出来**
典型的后台被系统杀掉了。把 Linphone 的电池优化设为「无限制」，国产 ROM 再开自启动。
同一 WiFi 下打开「内网直呼」更稳，它不依赖推送。

**接通后前几秒是哑的**
用 sip2sip 这类海外服务器时会出现：媒体被塞进境外 MediaProxy 收敛，前 6 秒没声音。
自建 SIP 或走内网直呼可以彻底避开。

**声音发闷 / 卡顿 / 像被拉长**
proot 里后台进程的 timer slack 默认 40ms，会把 20ms 的音频帧推成 40~60ms。
本插件已在启动 baresip 前把 `/proc/self/timerslack_ns` 压到 1µs，若被系统策略覆盖会复现。

**部署在云服务器上，baresip 起不来 / 日志提示 module not found**
多半是 `module_path` 不对。插件会按 Ubuntu、源码编译、arm64 等常见路径自动兜底，
并在日志里写「改用 xxx」。一条兜底记录都没有，说明这些路径都不存在。

**自建 SIP 改了端口或只开 TCP，插件还在连 5060**
把 `server` 写成 `host:端口`、`transport` 填 `tcp` 就行；`server` 留空时会取
`caller_aor` 里 `@` 后面的域名，同样支持带端口。

**打了试拨电话，正式音色被换了？**
不会。试拨固定用 edge 朗读，只为听「通不通、响不响」，不改配置里的后端。

**改了页面没生效**
宿主会缓存侧边栏页面。关掉面板再打开。

## 隐私

- 插件不上报任何数据，没有遥测、没有统计接口。
- **不录音、不采集麦克风。** 整条链路只往手机那头播放，你说的任何话都不会被接收到本地。
- 页面读取配置时，密码类字段只回「有没有填」，不回明文。
- 内网扫描只在本机所在网段内发 SIP OPTIONS 问询，不建立会话、不响铃、不读取对方信息。
- 检测到公共网络（本网段活跃设备超过 8 台）时，停止扫描网关与陌生设备，
  整段找回改为按 5/15/30/60 分钟逐级退避，临近任务触发再压回 5 分钟。
